# SOP 09 - Build

Implements: Stage 10.1.

## Purpose

Clone the niche template, overlay per-client brand-dna values, run the Vite build, and validate the output. The result is a production-ready dist/ folder ready for deploy.

## Inputs (per-client)

```
templates/trades-roofing-plumbing-electrical/  (niche template)
clients/[Client Name]/Pipeline Data/brand/brand-dna.json
clients/[Client Name]/Pipeline Data/hero-image/hero-final.{png,webp}
clients/[Client Name]/[Client Name] Assets/  (badges, project photos, logo)
website-factory/.claude/skills/frontend-design/SKILL.md
website-factory/.claude/skills/impeccable/CLAUDE.md
```

## Procedure

1. Run tools/build-from-template.py --client "[Client Name]" --niche trades-roofing-plumbing-electrical. This copies the niche template into the client folder and substitutes brand-dna sentinels.
2. Verify no __REQUIRED__ sentinels survive in src/config/brand-dna.js. If any survive, halt and identify which fields are missing from brand-dna.json.
3. Copy hero-final.{png,webp} to public/hero.{png,webp}.
4. Copy logo files to public/logo.svg (or .png) and public/logo-white.svg.
5. Copy trust badge SVGs to public/badges/. If MANUAL-DROP-NEEDED.md is present in niche-playbook/trust-badges/, alert student to manually drop badge files before build.
6. Copy project photos to public/work/. Minimum 6 files (before/after pairs). If fewer than 6, flag to student.
7. Run npm install --no-audit --no-fund inside the client website directory.
8. Run npm run build. Capture output. If build fails, read the error, identify the failing component or import, fix it, and re-run. Do not skip to deploy with a broken build.
9. Verify dist/index.html: confirm no __REQUIRED__ sentinels survived, confirm Google Fonts link is present, confirm canonical meta tags are set.

## Critical section order — do not reorder

The homepage renders sections in this exact order. Any deviation fails Gate 1 and Gate 6:

1. NavBar
2. MobileCTABar (fixed position, outside normal flow)
3. Hero
4. TrustBar (immediately after Hero — no sections between)
5. Services
6. WhyUs
7. Process
8. Reviews
9. Gallery
10. ServiceAreas
11. FinalCTA
12. Footer

TrustBar must immediately follow Hero. This is the single most conversion-critical structural rule for this niche. Homeowners who arrive via Google Search need to see proof (reviews, certifications) within the first scroll — not after services or differentiators.

## Pass criteria

- npm run build exits 0.
- dist/index.html exists and contains content.
- No __REQUIRED__ sentinels in dist/index.html.
- Phone number (from brandDNA.contact.phone) appears at least twice in the rendered HTML (nav + hero).
- TrustBar renders immediately after Hero in the DOM (no intervening section elements).
- MobileCTABar has fixed positioning and is hidden on md+ screens.

## When this stage halts

- Build fails with an import error: fix the import path and retry. If the missing component is a niche template component (not a client file), flag as a template defect and halt.
- brand-dna.json is missing required fields: halt and return to Stage 7.
- Hero image is missing: halt. Do not build without the hero image.
- Fewer than 6 project photos: warn (do not halt). Student can build with placeholders but must supply real photos before delivery.

## Niche-specific notes

The MobileCTABar is the highest-converting mobile element in this niche. It must render as a fixed element outside the main content flow, not inside a section. Verify it uses the accent color (#f5a623 by default) and that the tap-to-call link uses the correct tel: protocol with the client's phone number.

The Hero form has exactly 4 fields: Full Name, Phone Number, Service Needed (dropdown), Email Address. Do not add or remove fields. The "Service Needed" dropdown options should match the client's actual services from brand-dna.json services array.
