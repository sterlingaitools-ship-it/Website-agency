# SOP design-fidelity-qa - Design Fidelity QA

Implements: Stage 10.4a.

## Purpose

Compare the built client site against the niche template reference render using SSIM scoring. Verify every homepage section meets its visual fidelity threshold. Flag structural deviations that would reduce conversion below the niche baseline.

## Inputs (per-client)

```
clients/[Client Name]/[Client Name] Website/dist/

website-factory/.claude/skills/impeccable/CLAUDE.md
website-factory/.claude/skills/impeccable/skill/reference/audit.md
```

## Procedure

1. Take a full-page screenshot of the built site (localhost or preview URL).
2. Load design-fidelity.md to get per-region SSIM weights and thresholds.
3. For each region in the table, crop the screenshot to the region bounds and compute SSIM against the niche reference render. Log the score.
4. Flag any region below its threshold as WARN. Flag Hero below 0.85 or TrustBar below 0.83 as HALT.
5. Run the per-region visual checklist from design-fidelity.md. Log pass/fail per item.
6. Write the QA report to clients/[Client Name]/Pipeline Data/qa/design-fidelity-report.md.

## Pass criteria

- Hero SSIM >= 0.85.
- TrustBar SSIM >= 0.83.
- TrustBar renders immediately below Hero with no intervening sections.
- NavBar contains a visible phone number.
- All soft-warn regions above 0.70 (no complete failures below the floor).

## When this stage halts

- Hero SSIM below 0.85: halt. Diagnose which visual element diverged (layout split, image placement, form position, or color) and return to Stage 10.1 for a rebuild.
- TrustBar SSIM below 0.83: halt. Most common cause is TrustBar being moved below Services or WhyUs. Fix section order and rebuild.
- TrustBar is not immediately below Hero: halt regardless of SSIM score. This is a structural conversion failure.

## Niche-specific notes

The two HALT regions (Hero and TrustBar) are the conversion core of this template. A homeowner who arrives from Google Search sees the hero and trust bar before anything else. If the trust bar is displaced or the hero layout deviates significantly from the split-screen proof-first pattern, conversion will fall.

The most common fidelity failure in this niche template is the trust bar being pushed below the fold by an oversized hero. The Hero section has a max height of 780px on desktop. If a client's hero image is unusually tall, the build agent must constrain it with max-h-[780px] rather than allowing it to push TrustBar off screen.
