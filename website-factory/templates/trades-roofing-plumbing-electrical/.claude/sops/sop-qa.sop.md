# SOP sop-qa - SOP Compliance QA

Implements: Stage 10.4b.

## Purpose

Verify every section of the built site meets the niche SOP requirements from sop-compliance.md. This is a structural and copy audit, not a visual one. It checks that required elements are present, correctly wired to brand-dna, and following the niche conversion rules.

## Procedure

1. Load sop-compliance.md. Work through each section's checklist items in order.
2. For each item, inspect the built HTML (dist/index.html) or the source JSX to verify the element is present and correct.
3. Log pass or fail for each item. On fail, note the specific gap (e.g., "form submit button reads 'Submit' instead of 'Get My Free Quote'").
4. Run the universal checks at the bottom of the checklist (no hardcoded copy, no inline styles, alt text, keyboard accessibility, no em-dashes).
5. Write the QA report to clients/[Client Name]/Pipeline Data/qa/sop-compliance-report.md.

## Critical niche checks (these fail the gate if not present)

- **Phone in NavBar**: brandDNA.contact.phone must appear as a clickable link in the navigation bar on every page.
- **Trust bar position**: The TrustBar section must render immediately after the Hero. No other section may appear between them.
- **Hero form field count**: The quote form in the Hero section must have exactly 4 fields: Full Name, Phone Number, Service Needed (dropdown), Email Address.
- **Submit button text**: The form submit button must read "Get My Free Quote" — not "Submit", not "Send", not "Request Quote".
- **Reviews format**: The Reviews section must render named testimonials (full name + city/state + outcome sentence), not anonymous star ratings or generic review widgets.
- **MobileCTABar**: Must be present and fixed to the bottom of the viewport on mobile screens. Must use the accent color background. Must be hidden on md+ screens.

## Pass criteria

- All critical niche checks pass.
- No hardcoded copy strings in any component (all visible text comes from brandDNA.* paths).
- All images have non-empty alt attributes.
- All form inputs have associated labels (visible or aria-label).
- No em-dashes in any rendered text.

## When this stage halts

- Any critical niche check fails: halt. Return to Stage 10.1 build with specific instructions to fix the failing element.
- More than 3 non-critical checklist items fail: halt. A site with multiple SOP gaps will underperform vs. the niche baseline.

## Niche-specific notes

The Reviews section format is a common failure point. Generic implementations often render a star-rating widget (e.g., a Google Reviews embed with only the star count). This template requires named photo testimonials with outcome sentences. If the build agent produced a generic star widget, it must be replaced with the Reviews.jsx component from the niche template which renders brandDNA.reviews.items in the named-photo card format.

UX writing check: the form header must read "Get Your Free Estimate" (from copy-locks.json). Any deviation from this exact phrase should be flagged, as this phrase has been optimized for the homeowner's mental model in this niche (they want an estimate, not a quote, not a consultation).
